## Fixed: convert-video.js + video-to-audio.js render crash (pre-existing bug)

Both tools were registered "done" but **crashed on load** with:
`TypeError: Cannot read properties of undefined (reading 'innerHTML')` at tool.js

**Root cause:** They used the OLD factory pattern:
```js
const { optionsArea, runFFmpeg } = createVideoTool({ container });
```
But `createVideoTool` now takes a config object (`optionsHTML`, `onProcess`, ...) and **returns a render function**. Destructuring a function yields `undefined`, so `optionsArea.innerHTML +=` threw.

**Fix:** Rewrote both with the current pattern (like `compress-video.js`):
```js
export const render = createVideoTool({
  optionsHTML: `...`,
  actionBtnLabel: "...",
  async onProcess(ffmpeg, inputName, videoInfo, tctx) { ... }
});
export function destroy() {}
```

**Also:** `convert-video.js` used `libvpx-vp9` for WebM output — VP9 encoder crashes the wasm core (see VP9 gotchas in MEMORY.md). Switched to `libvpx` (VP8), confirmed via Context7 the API pattern matches. Option label updated to "WebM (VP8 — best for web)".
