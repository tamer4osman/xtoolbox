## CI: Node 20 deprecation - bundle-size job

- GitHub announced Node 20 removal on Actions runners (removal fall 2026). `andresz1/size-limit-action@v1` (latest v1.8.0, Apr 2024) still declares `runs.using: node20` -> CI logs showed the "Node 20 is deprecated" banner + `DEP0169 url.parse()` warning.
- Replaced the third-party action in `.github/workflows/ci.yml` `bundle-size` job with a native run:
  - `npx size-limit --json` (captures exit_code + result via `$GITHUB_OUTPUT`, tolerates non-zero exit to still report).
  - `actions/github-script@v7` posts size result as a PR comment (default GITHUB_TOKEN).
  - Separate "Fail on size limit exceeded" step (`exit_code != '0'`) preserves budget enforcement.
- **Lesson:** `continue-on-error: true` on the size step would have swallowed the non-zero exit (no more budget enforcement) - keep the run un-wrapped, capture `$?`, then hard-fail a separate step. Also don't drop the preceding `npm run build` step (size-limit measures `dist/`).

## CI: bundle-size — preset + stale config fix ✅

- **Root cause of the flaky/hung size job:** `@size-limit/preset-app` re-exports `[...file, ...time]`; the `time` plugin launches headless Chrome via estimo even though the config only defines byte limits (`gzip: true`, no `time`). That Chrome spin is what showed up as a 30s local timeout (missing Chrome WS endpoint) and the CI `exit 143` (SIGTERM) cancellations. Also the main-entry glob `dist/assets/index-*.js` matched **nothing** (Vite 8 names the entry `main-<hash>.js`) so the "Main bundle" check measured 0 in CI.
- **Fix (2 parts):**
  1. Replaced `@size-limit/preset-app@^11.2.0` (devDep) with `@size-limit/file@^11.2.0` (dep) so no Chrome/time plugin is loaded (−74 packages, lockfile −969 lines).
  2. Fixed config in `package.json`: `Main bundle` glob → `dist/assets/main-*.js`, and `Total JS` limit raised 2 MB → 3 MB.
- **Clean-build measurement** (matters because local `dist/` is polluted by the `emptyOutDir: false` Avast workaround — 90+ stale `main-*.js` chunks). Built to a fresh dir (`npx vite build --outDir dist-clean`; `emptyOutDir: false` doesn't matter on a new dir), then measured: 433 JS files, main entry `main-EUd73pmg.js` raw 90.8 KB / **gzip 23.8 KB**, all JS raw 7.08 MB / **gzip 2.18 MB**. `npx size-limit --json` against that dir: Main 24,348 B (vs 200 kB ✓), Total 2,279,873 B (vs 3 MB ✓), exit 0.
- Reverted package.json paths back to `dist/assets/*` (the dist-clean path was just for measurement), kept `3 MB` budget. Format check green. Temp dirs (`dist-clean`, `dist-backup`, `dist-temp`, `dist-test`, `dist2`) deleted.
- **Lesson:** When a check reads a glob of stale artifacts, branch a branch whose dir (ephemeral `--outDir`, CI uploads) and get the true single-entry size — a locally over-budget result isn't a regression if the numbers vanish on a clean build. Also verify whether a preset pulls in plugins your config never needs (here: it forced Chrome)`.

## CI: bundle-size — comment step 403 (fixed in cf4cf8b+)

- After the plugin+glob fix, size-limit passed on CI (Main 24,301 B ≤ 200 kB ✓; Total 2,278,533 B ≤ 3 MB ✓) but `actions/github-script@v7` failed to post the Bundle Size comment: **`Resource not accessible by integration` (403)**.
- Root cause: the `bundle-size` job had no `permissions`, so the default `GITHUB_TOKEN` was read-only — creating an issue/PR comment needs `pull-requests: write`.
- Fix: added `permissions: pull-requests: write` to the `bundle-size` job in `.github/workflows/ci.yml` (job-level, not workflow-level; `issues: write` not required).
- **Lesson:** anytime a workflow post-comments on the PR, grant `pull-requests: write` at the job (or workflow) level — a 403 from github-script almost always means a missing `permissions` block, not bad code.

## CI: fallow dead-code — @size-limit/file marked unused

- After the preset swap, CI `code-health` step `npx fallow dead-code --changed-since=HEAD~1` failed (exit 1):
  - `@size-limit/file` flagged as an **unused dependency** — it's a CLI plugin invoked via the package.json `size-limit` config, never `import`ed by source. Config-driven deps belong in `.fallowrc.json` `ignoreDependencies`. Swapped the old `@size-limit/preset-app` entry there.
  - The `overrides` block (`estimo.nanoid`, `ip-address`) was flagged **unused** — both only existed to pin `@size-limit/preset-app`'s transitive estimo→puppeteer chain; once the preset was dropped neither remained in `package-lock.json`. Deleted the whole `overrides` block.
- Verified locally: `npx fallow dead-code --changed-since=HEAD~1` → "No issues found" (exit 0); `npm run format:check` green (after oxfmt on `.fallowrc.json`); lockfile no drift.
- **Lesson:** when swapping a CLI/config-driven plugin, (a) update its `ignoreDependencies` entry — fallow sees no import so marks it unused — and (b) sweep `package.json` `overrides` for pins that only existed for the removed package's transitive tree.
