### TestSprite lessons (write it down, future-you!)
- Stale `testsprite_tests/tmp/execution.lock` from a killed process blocks re-runs — delete manually before regenerating.
- Test code executes cloud-side via tunnel; local process just polls. So a slow/flaky tunnel makes the whole flow feel stuck.
- Bootstrap: config lives at `testsprite_tests/tmp/config.json` (not `.testsprite/`); the first-time init needs to run through the MCP bootstrap call, not the CLI.
- The `generate_code_and_execute` step writes scripts under `testsprite_tests/` and a raw report under `testsprite_tests/tmp/raw_report.md`.
- TestSprite's own report template lives at `dist/assets/testsprite-mcp-test-report-template.md` inside the npx cache.
